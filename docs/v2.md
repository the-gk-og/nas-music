# nas-music v2 spec

v2 turns nas-music into a self-hosted, multi-user "Spotify": invite-only accounts, per-user taste, three
clients (Android, web player, desktop app) that see and control each other, and a Musicolet-style
player UI. This file is the contract for the parallel v2 work. **`api/openapi.yaml` is updated from
this file by the server-core session in its first commit**; until then this file is authoritative.
Where they disagree, raise it — don't guess.

Everything stays free and open source (AGPL-3.0), and must run on the i5-3470 NAS.

## 1. Decisions (from the owner)

| Topic | Decision |
| --- | --- |
| Accounts | Multi-user, **invite-only**. Only admins create invites. Username + password. |
| Connecting | Any client: enter a server address (LAN `https://192.168.68.2:8443` or `https://music.<domain>`), then log in with username/password. QR pairing stays as an optional shortcut. |
| Taste | Everything about listening is **per user**: events, favourites, ratings, thumbs, mixes, recommendations, suggestions, playlists, queues. The music library and audio analysis are shared. |
| Streaming | Stream like Spotify. Offline downloads still exist on Android but are **off by default** (Settings switch "Offline favourites"). Nightly mix download only runs when that switch is on. |
| Clients | Android app (redesigned), web player served by the server, desktop app = **Tauri v2** wrapping the web player. |
| Device control | Spotify-Connect-style: every signed-in client is a device; any device can see what's playing on the user's other devices, control it, and transfer playback. |
| Watch | Galaxy Watch shows cover art + controls through the phone's media session (artwork must be set as bitmap data). A standalone Wear OS app is a later phase. |
| UI | Looks and works like **Musicolet** (screenshots in the owner's message): dark, bottom tab bar, album grid, multiple named queues, tap cover → lyrics, song-info sheet, equalizer. Our own icons and name; no Musicolet branding. |

### Out of scope for v2 (file-modifying features — the library is read-only)
Edit tags, move to folder, audio cutter, set as ringtone, delete permanently, bookmarks/notes.
Lyrics *editing* is in scope but saved on the server as a per-track override, never written to the file.

## 2. Database (schema v2)

Server core owns the schema and writes a **migration from v1** (the NAS already has a live v1 database).
`schema_version` becomes 2. Migration rules:
- Create user `admin` (is_admin=1) whose `password_hash` = config `admin_password_hash`. All existing
  per-user data (events, starred/rating/blocked, mixes, taste_snapshots, suggestions, devices) is
  assigned to that user.
- `admin_username` config key (default `admin`) names that first user.

New / changed tables (only the deltas; keep everything else from v1):

```sql
CREATE TABLE users (
  id TEXT PRIMARY KEY, username TEXT NOT NULL UNIQUE COLLATE NOCASE, password_hash TEXT NOT NULL,
  is_admin INTEGER NOT NULL DEFAULT 0, disabled INTEGER NOT NULL DEFAULT 0,
  created_at TEXT NOT NULL, last_login TEXT);

CREATE TABLE invites (
  code TEXT PRIMARY KEY, created_by TEXT NOT NULL REFERENCES users(id), created_at TEXT NOT NULL,
  expires_at TEXT NOT NULL, note TEXT, used_by TEXT REFERENCES users(id), used_at TEXT);

-- devices: add user_id (NOT NULL), kind ('android'|'web'|'desktop'|'watch'|'other'), and app_version.
-- pair_codes: add user_id (the QR is created by a signed-in user and logs the phone in as that user).

-- Per-user track state replaces tracks.starred_at / rating / blocked (drop those columns after copying).
CREATE TABLE user_tracks (
  user_id TEXT NOT NULL REFERENCES users(id), track_id TEXT NOT NULL REFERENCES tracks(id),
  starred_at TEXT, rating INTEGER, blocked INTEGER NOT NULL DEFAULT 0,
  play_count INTEGER NOT NULL DEFAULT 0, skip_count INTEGER NOT NULL DEFAULT 0, last_played TEXT,
  PRIMARY KEY (user_id, track_id));

-- events, mixes, taste_snapshots, suggestions: add user_id NOT NULL (+ index).
-- suggestions: UNIQUE becomes (user_id, release_group_mbid).

CREATE TABLE playlists (
  id TEXT PRIMARY KEY, user_id TEXT NOT NULL REFERENCES users(id), name TEXT NOT NULL,
  created_at TEXT NOT NULL, updated_at TEXT NOT NULL);
CREATE TABLE playlist_tracks (
  playlist_id TEXT NOT NULL REFERENCES playlists(id) ON DELETE CASCADE, position INTEGER NOT NULL,
  track_id TEXT NOT NULL REFERENCES tracks(id), added_at TEXT NOT NULL, PRIMARY KEY (playlist_id, position));

-- Musicolet-style multiple named queues, shared by all of a user's devices. Max 20 per user.
CREATE TABLE queues (
  id TEXT PRIMARY KEY, user_id TEXT NOT NULL REFERENCES users(id), name TEXT NOT NULL,
  slot INTEGER NOT NULL,             -- 1..20, display order and number ("20. Search: conver")
  current_index INTEGER NOT NULL DEFAULT 0, position_ms INTEGER NOT NULL DEFAULT 0,
  created_at TEXT NOT NULL, updated_at TEXT NOT NULL, UNIQUE (user_id, slot));
CREATE TABLE queue_tracks (
  queue_id TEXT NOT NULL REFERENCES queues(id) ON DELETE CASCADE, position INTEGER NOT NULL,
  track_id TEXT NOT NULL REFERENCES tracks(id), PRIMARY KEY (queue_id, position));

-- Per-user lyrics edits; never written to the music file.
CREATE TABLE lyrics_overrides (
  user_id TEXT NOT NULL REFERENCES users(id), track_id TEXT NOT NULL REFERENCES tracks(id),
  raw TEXT NOT NULL, updated_at TEXT NOT NULL, PRIMARY KEY (user_id, track_id));

-- Last known playback state per user (also held in memory by the Connect hub).
CREATE TABLE playback_state (
  user_id TEXT PRIMARY KEY REFERENCES users(id), state TEXT NOT NULL, updated_at TEXT NOT NULL);  -- JSON

-- tracks: add composer, lyricist, comment, album_artist, bitrate, sample_rate, bits_per_sample,
-- channels, codec, folder (relative dir, for the Folders tab). Filled by the scanner.
```

## 3. AI engine boundary (`server/nasmusic/ai/api.py`, v2 signatures)

Analysis stays global. Everything else takes a `user_id`.

```python
analyse_pending(conn, cfg, limit=None) -> int                          # unchanged
run_nightly(conn, cfg) -> dict[str, list[str]]                         # all active users; {user_id: mix ids}
run_nightly_for_user(conn, cfg, user_id) -> list[str]
more_like(conn, cfg, user_id, track_id, minutes=40) -> str             # KeyError if unknown/unanalysed
explain(conn, cfg, user_id, track_id) -> tuple[str, list[str]]
run_weekly_discovery(conn, cfg) -> dict[str, int]                      # per user
```
The recommender reads only that user's `events` and `user_tracks`. A brand-new user with no history
gets cold-start mixes from library-wide signals (most played across users, recently added, sound
diversity) until they have ~20 plays. Users never see each other's history.

## 4. HTTP API changes (`/api/v1`)

Auth header unchanged (`Authorization: Bearer <deviceToken>`). The web player may instead use the
httpOnly cookie `nm_session` (same token) set by login with `"cookie": true`. Responses are JSON;
errors are `{"detail": "..."}` with 4xx codes. Login/register are rate-limited (5 tries/min/IP → 429).

### Public
| Method & path | Body → Response |
| --- | --- |
| `GET /health` | unchanged |
| `GET /server-info` | → `{serverId, name, version, lanUrl, tunnelUrl, certSha256, registration: "invite"}` — lets a client logged in via one address learn the other and pin the LAN cert. |
| `POST /auth/login` | `{username, password, deviceName, deviceKind, cookie?}` → `Session` |
| `POST /auth/register` | `{inviteCode, username, password, deviceName, deviceKind, cookie?}` → `Session` (409 username taken, 403 bad/used/expired invite). Username 3–32 chars `[A-Za-z0-9_.-]`, password ≥ 8. |
| `POST /pair` | unchanged shape; the code now belongs to a user and logs the device in as them. |

`Session = {userId, username, isAdmin, deviceId, deviceToken}`

### Signed in (any user)
| Method & path | Notes |
| --- | --- |
| `POST /auth/logout` | revokes this device token, clears cookie |
| `GET /me` · `PUT /me/password {current, new}` | |
| `GET /me/devices` · `DELETE /me/devices/{id}` | user's own devices (name, kind, lastSeen, online) |
| `POST /me/pair-code` | → `{pairCode, qrPayload}` for adding another phone by QR |
| `GET /library/folders?path=` | → `{path, parent, folders:[{name, path, trackCount}], tracks:[Track]}` (path relative to library root; `""` = root) |
| `GET /library/genres` · `GET /library/genres/{genre}/tracks` | |
| `GET /library/tracks?sort=title|added|year&offset&limit` | "All songs" |
| `GET /library/tracks/{id}/info` | → `TrackInfo`: Track + `{fileName, folder, albumArtist, composer, lyricist, comment, codec, bitrateKbps, sampleRate, bitsPerSample, channels, fileBytes}` |
| `GET /lists/{kind}` | smart lists, kind ∈ `favourites`, `recently_added`, `recently_played`, `most_played`, `not_played` → `[Track]` (paged) |
| `GET /playlists` · `POST /playlists {name}` · `GET/PATCH/DELETE /playlists/{id}` | |
| `POST /playlists/{id}/tracks {trackIds, position?}` · `DELETE /playlists/{id}/tracks/{position}` · `POST /playlists/{id}/move {from, to}` | |
| `GET /queues` · `POST /queues {name, trackIds, startIndex?}` · `GET/PATCH/DELETE /queues/{id}` | max 20; creating a 21st replaces the oldest unused, like Musicolet |
| `POST /queues/{id}/tracks {trackIds, position?|"next"|"end"}` · `DELETE /queues/{id}/tracks/{position}` · `POST /queues/{id}/move {from, to}` · `POST /queues/{id}/save-as-playlist {name}` | |
| `GET /tracks/{id}/lyrics` | unchanged shape + `source` may be `"user"` (override) and new field `canEdit: true` |
| `PUT /tracks/{id}/lyrics {raw}` · `DELETE /tracks/{id}/lyrics` | per-user override (LRC or plain); DELETE reverts to file lyrics |
| existing endpoints | favourites, mixes, more-like, why, events, suggestions, sync manifest, stream, art, lyrics: **now scoped to the calling user**. `Track.starred/rating` are the caller's. |

### Admin only (`isAdmin`)
| Method & path | Notes |
| --- | --- |
| `GET /admin/invites` · `POST /admin/invites {note?, expiresInDays=7}` → `{code, url, expiresAt}` · `DELETE /admin/invites/{code}` | `url` = `<tunnelUrl or lanUrl>/join/<code>` (web page that registers and opens the player) |
| `GET /admin/users` · `PATCH /admin/users/{id} {disabled?, isAdmin?}` · `POST /admin/users/{id}/reset-password {new}` | can't remove the last admin |

## 5. Connect: live device control

WebSocket: `wss://<server>/api/v1/connect` (auth: bearer token in the `Authorization` header, or
`?token=` for browsers, or the `nm_session` cookie). One socket per client. JSON messages
`{"type": ..., ...}`. Works over the Cloudflare tunnel.

**Model.** Each user has one *playback state* and at most one *active device*. Only the active device
plays audio. Other devices are remotes. State is held in memory by the server hub and persisted to
`playback_state` every few seconds and on change.

```jsonc
// PlaybackState
{ "activeDeviceId": "d1"|null, "queueId": "q1", "index": 3, "trackId": "t9",
  "positionMs": 61234, "positionAt": "2026-11-18T09:00:00.000Z",   // position extrapolates while playing
  "playing": true, "volume": 0.8, "shuffle": false, "repeat": "off"|"all"|"one",
  "speed": 1.0, "rev": 42 }                                           // rev increments on every change
```

Client → server:
| type | fields | meaning |
| --- | --- | --- |
| `hello` | `deviceName, kind, canPlay, appVersion` | first message |
| `state` | `PlaybackState` (from the active device only) | report on every change + every 5 s while playing |
| `command` | `action, args, targetDeviceId?` | `play`, `pause`, `next`, `prev`, `seek{positionMs}`, `setVolume{volume}`, `setShuffle{on}`, `setRepeat{mode}`, `playQueue{queueId, index}`, `playTracks{trackIds, index, queueName}` (creates/replaces a queue), `setSpeed{speed}` |
| `transfer` | `toDeviceId, play` | move playback to another device |
| `ping` | | keep-alive every 25 s |

Server → client:
| type | fields | meaning |
| --- | --- | --- |
| `welcome` | `deviceId, devices[], state` | after hello |
| `devices` | `devices: [{id, name, kind, canPlay, online, isActive}]` | whenever the list changes |
| `state` | `PlaybackState` | broadcast to all the user's devices on change (rev ordered) |
| `command` | `action, args, fromDeviceId` | delivered to the active device to execute |
| `takeover` | `state` | you are now the active device: load queue, seek to positionMs, play if `state.playing` |
| `release` | | you are no longer active: stop audio, keep UI as remote |
| `queues` | `queueId` | a queue changed elsewhere; refetch it |
| `pong` | | |

Rules:
- A device that starts playback locally (user presses play on it) sends `transfer{toDeviceId: self}`
  first; the previous active device gets `release`.
- If the active device disconnects for > 15 s, the server marks `playing=false` and keeps
  `activeDeviceId` so a reconnect resumes control; any device can `transfer` to itself.
- Commands from remotes are applied by the active device, which then reports `state`. If there is
  no active device, `play` from a remote makes that remote active (if it can play).
- Events (`play`/`skip`) are still recorded only by the device that actually played the audio.

## 6. Client behaviour shared by Android, web and desktop

- **Connect screen**: server address field (accepts `192.168.68.2:8443`, `https://…`), then
  username/password, plus "Join with invite code" and (Android) "Scan QR".
  On a LAN address with a self-signed cert: show the SHA-256 fingerprint and ask to trust it
  (trust-on-first-use), unless it matches `certSha256` already learned via `/server-info` over the
  tunnel. After login, save both addresses from `/server-info` and switch automatically (LAN first).
- **Devices button** (speaker icon, like Spotify's): lists the user's online devices; tap to transfer.
  When another device is active, the now-playing bar shows "Playing on <device>" and acts as a remote.
- **Lyrics**: tapping the cover art on Now Playing flips to the lyrics view (tap again to flip back).
  Header: source dropdown (Embedded / .lrc file / Your edit), edit (pencil), text size (Tt), close (✕).
  If none: *Could not find embedded lyrics in tags of "<file name>" file.* with a "Add lyrics"
  button that opens the editor. Synced lyrics highlight + auto-scroll + tap-to-seek (Android done).
- **Equalizer** (local to each device, per audio output — e.g. one profile per Bluetooth device):
  on/off, 10-band EQ (31.5, 63, 125, 250, 500, 1k, 2k, 4k, 8k, 16k Hz, ±12 dB) with presets (Flat,
  Bass, Vocal, Treble, Rock, Pop, Classical, Custom), bass boost %, surround/virtualizer %, preamp
  (Headroom −6 dB / Off / Boost +1 dB + slider), volume, Stereo/Mono, channel balance.
  Android: an ExoPlayer `AudioProcessor` chain (biquad peaking filters) so all 10 bands work on any
  phone. Web/desktop: Web Audio `BiquadFilterNode`s + `GainNode` + `StereoPannerNode` + mono merge.
- **Play speed & pitch**, **A-B repeat**: local player features.
- **Watch / lock screen** (Android): MediaSession metadata includes title, artist, album, duration and
  `artworkData` (a ≤ 512 px bitmap, not only a URI) so Galaxy Watch media controls show cover art.

## 7. Musicolet-style UI (Android, and the same structure in the web player)

Dark theme (true black backgrounds, white text, one accent colour — green `#4ADE80`-ish). Bottom tab
bar, in this order, icon only, active tab underlined with the accent:

1. **Queues** — the current queue as a reorderable list (drag handle ☰, cover thumb, title,
   artist, album, duration, "…" menu; current track outlined in accent). Header: queue selector
   dropdown showing `N. Name` (e.g. `20. Search: conver`), close ✕, play ▶, sort, `index / count`
   and total time ⏱, save 💾 (save as playlist), "…" (clear, rename, delete queue).
2. **Now Playing** — large cover (tap → lyrics), title / artist / album centred; action row:
   ♡ favourite, ⓘ song info, add-to-playlist, "…" more; repeat and shuffle on the right; seek bar
   with times; bottom row: volume, previous, play/pause, next, equalizer. Background tinted from the
   cover's dominant colour (subtle gradient). Devices button in the top bar.
3. **Folders** — browse library folders.
4. **Albums** — 3-column grid of cover cards with the title under each (ellipsised); top bar:
   search field "Search an album…", sort, settings ⚙.
5. **Artists**.
6. **Genres** (tag icon).
7. **Playlists** — All songs, Favorites, Recently added, Recently played, Most played, Not played;
   "Your playlists" list; "+ New Playlist".
8. **Search** — across songs, albums, artists.
9. **"…" overflow** — Settings, Equalizer, Devices, Mixes for you (daily mixes), Discover
   (suggestions), Account, Admin (admins: invites, users).

Song "…" menu: Show lyrics, A-B repeat, Play speed and pitch, Play next, Add to a queue, Add to
playlists, Go to album, Go to artist, More like this, Song info, Share (copies a link to the web player).
Tapping a song in any list plays that list as a new queue (Musicolet behaviour); long-press offers
"Play next" / "Add to queue".

**Song info** sheet: cover thumb + file name, location (folder path), Title, Album, Artist,
Album-Artist, Composer, Genre, Lyricist, Track number, Disc number, Year, Comment, Duration, plus
format line (e.g. "FLAC · 16-bit · 44.1 kHz · 912 kbps"). `[unknown]` for empty fields. Read-only.

## 8. Web player and desktop app

- `web/` — Vite + Svelte 5 + TypeScript SPA. Built to static files and served by the server at `/`
  (admin pages move to `/admin`). Same tabs as Android (sidebar on wide screens, bottom bar on
  phones), same Now Playing / lyrics / queues / song info / equalizer, Connect devices menu,
  keyboard shortcuts (space, ←/→ seek, shift+←/→ prev/next), Media Session API for OS media keys.
  `/join/<code>` registers with an invite. Plays `/stream/{id}?format=opus` via `<audio>`
  (Safari: request `format=flac`… or AAC later).
- `desktop/` — Tauri v2 app (Linux AppImage/deb, Windows, macOS) bundling the same web build. On first
  run shows the Connect screen (server address → login) and talks to the server cross-origin with the
  bearer token. Extras: tray icon with play/pause/next, global media keys, native notifications on
  track change, single instance, remembers window size.
- Server: CORS allow-list for the Tauri origins (`tauri://localhost`, `http://tauri.localhost`) with
  bearer auth; Docker image gains a Node build stage that builds `web/` into the image.

## 10. Listening context collection (opt-in, stays on the user's own server)

The owner wants richer, even invasive, signals as long as they only go to their own server. Each
signal has its own switch under **Settings → Data & recommendations**, per user and per device,
with a one-line explanation of what it collects and how it's used. Defaults: the v1 signals
(play/skip/star/rating/thumbs) are always on; everything below is **off until switched on**, with a
"Turn everything on" button. Nothing is ever sent anywhere except this server.

Events gain an optional `context` object (JSON column `events.context`), filled only with enabled signals:

| Switch | Field(s) | How it's gathered (no Google Play Services) |
| --- | --- | --- |
| Listening details | `seeks[]`, `volumeChanges[]`, `repeatOfPrevious`, `addedFrom` (search/queue/mix/…), `sessionId`, `sessionPosition` | player events |
| Audio output | `output`: `speaker` / `wired` / `bluetooth:<device name>` / `cast` / `car` | AudioManager / MediaRouter; web: `navigator.mediaDevices` label when permitted |
| Device & network | `deviceKind`, `network`: `wifi` / `cellular` / `ethernet`, `charging`, `batteryPct`, `screenOn` | ConnectivityManager, BatteryManager, PowerManager |
| Movement | `motion`: `still` / `walking` / `running` / `vehicle`, `cadenceSpm` | step detector + accelerometer + speed from location if enabled (no Activity Recognition API) |
| Location | `place`: user-named cluster (`home`, `work`, `gym`, `place-3`) + `geohash5` (~5 km) | Android `LocationManager` (fused provider not used). Raw coordinates never leave the phone; the phone clusters them and sends the cluster label + coarse geohash. |
| Weather | `weather`: condition, temp °C | **server-side** from `geohash5` via Open-Meteo (free, no key, open data); cached hourly |
| Search history | `searchQuery` on events that came from a search | app |
| Time & calendar context | `localHour`, `weekday`, `holiday` (local public holidays from a bundled open dataset) | device clock — no calendar access |
| Watch health (later, with the Wear OS phase) | `heartRate`, `workout` | Health Connect (`androidx.health.connect`, Apache-2.0) |

Server: `user_settings(user_id, key, value)` stores the switches (synced to all the user's devices via
`GET/PUT /me/settings`). `GET /me/data` returns a summary (counts per signal, date range) and
`GET /me/data/export` a JSON export; `DELETE /me/data?signal=<name>|all` erases collected context
(and `all` also erases listening history after confirmation). Admins cannot read other users' context.

AI engine: context fields become optional model features (missing = unknown). Useful targets:
time/place/motion-specific mixes ("Gym", "Commute", "Late night at home"), output-aware picks
(car vs headphones), and better skip prediction. Context-based mixes only appear once there's
enough data for that context (≥ 30 plays in it).
